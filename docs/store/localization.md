# Play Store localization copy

Store copy for the seven languages the game ships. Paste each block into Play
Console under the matching language, which is what turns the listing into seven
listings rather than one English one reaching seven audiences.

Play Console takes these per language: **App name** (30 chars), **Short
description** (80 chars), **Full description** (4000 chars), and **promotional
text** (500 chars). Screenshots are images, so their captions are handled under
[In-app text](#in-app-text) instead - which matters, because a screenshot burned
with English text into the pixels cannot be localised after upload.

---

## Naming decision: the title stays "Arrow Puzzle"

The app name is **not** translated in any listing.

"Arrow Puzzle" is the term the game is indexed and reviewed under. Localising the
title per market means a different name in each store listing, which fragments
the review history, the rating average and the install attribution that Play
attributes back to a single listing. A localised name also loses every search
term the English listing has accumulated.

The localised **short descriptions** below therefore carry the local search terms
that a translated title would otherwise have provided, which is the intended
place for them.

| Language | App name | Locale folder |
| --- | --- | --- |

| German | Arrow Puzzle | `res/values-de` |

## English (default)

**Short description** (74/80)

> Slide arrows out of a packed board. Clear every one. One wrong tap costs a life.

**Full description**

> **Arrow Puzzle** is a slide-and-clear puzzle about knowing when *not* to move.
>
> Every arrow points somewhere. An arrow can only leave the board when every cell
> in front of it, all the way to the edge, is empty. Tap one with a clear route and
> it slides away. Tap one that is still blocked and it costs you one of your three
> lives.
>
> That is the whole game, and it is harder than it sounds.
>
> ▶ **Simple to play, hard to master** - one rule, no tutorial wall, endless small
> decisions.
> ▶ **3 stars per level** - every blocked tap costs you a star, so the top score
> means you saw every route before you touched the board.
> ▶ **5 packs, 50 hand-tuned levels** - each one built as a dependency chain, not a
> bigger grid.
> ▶ **Pinches and taps** - pinch to zoom on the larger boards, because losing a
> level to a misread arrow is no fun.
> ▶ **Plays offline** - no connection needed, no waiting.
>
> A few minutes of calm, or a long evening of chasing three stars. Both are good.
>
> Contains ads. Includes an optional rewarded ad that returns one life. Ads are
> shown to users outside the EEA, the UK and Switzerland with a consent choice;
> every other region gets the experience without the prompt.

**Promotional text**

> New: 50 levels across 5 packs, and the game now speaks 7 languages. Pick yours
> in Settings.

### 詳細説明 — 構成のみ（要ネイティブ Speakers 執筆）

**This section is an outline, not copy.** I have not written the Japanese long
description because a machine-drafted 700-character Japanese marketing paragraph
is worse than no draft at all - it reads as machine translation, it puts the
listing's quality in question, and it is expensive to spot-edit. The in-game
Japanese (`res/values-ja/strings.xml`) *is* finished; this is only the store
listing.

What follows is the structure a native speaker needs, with the character budget
for each section so the whole thing lands under Play Console's 4000-character
limit, and the source material it should be drawn from. The source material is
the finished Japanese in-game strings, so the listing and the app will say the
same thing in the same words.

| section | must accomplish | budget | draw from |
| --- | --- | --- | --- |
| Opening, 2 sentences | Frame the game as *judging when not to move*. Do not restate the title. | ~80 字 | the in-game one-liner plus the judgement framing |
| Rule explanation, 3 clauses | One direction → clear route → the two possible outcomes. Facts only, no adjectives. | ~120 字 | `how_to_rule_1`, `how_to_rule_2`, `how_to_rule_3` |
| One line | There is one rule; the difficulty is in how the arrows depend on each other. | ~40 字 | the pack/level design, which is the game's real hook |
| Bullet 1 | Playable in one step. No tutorial wall. | ~50 字 | `settings`-free framing; there is a first-play hint, nothing more |
| Bullet 2 | Three stars per level; a blocked tap costs a star, so a full score means you saw every route first. | ~50 字 | `celebration_perfect`, `a11y_level_stars` |
| Bullet 3 | Five packs, 50 levels, built as arrow dependency chains rather than bigger grids. | ~50 字 | pack and level structure |
| Bullet 4 | Pinch to zoom on the larger boards. | ~30 字 | `a11y_reset_zoom` and the zoom behaviour |
| Bullet 5 | Plays offline. | ~30 字 | offline behaviour |
| Closing, 2-3 lines | A few calm minutes or a long evening chasing three stars. | ~80 字 | tone, not fact |
| Ads, 3 sentences | Rewarded ad returns one life; consent flow for EEA/UK/CH; no prompt elsewhere. | ~120 字 | `status_ad_unavailable`, `action_continue_ad`, and the consent strings |

**プロモーションテキスト** — 未作成。全文説明の確定後に、英語版と同じ内容
（50 ステージ・5 パック・7 言語対応）で作成すること。

## In-app text

Not a Play Console field. It is here because the screenshot set is the one store
asset that **cannot** be localised after upload: text rendered into a PNG is not
translatable.

Two options, in the order we should try them:

1. **Upload per-language screenshots from localised device captures.** Capture on
   a device set to each locale, with the game in the chosen language, and upload
   each set under its language. This is the only way the screenshots actually
   match what the player sees. There is no technical obstacle - the game runs in
   all seven languages - only the effort of seven capture passes.
2. **Keep the screenshots text-free.** The current store art is already mostly
   device mockups. Captions can be a small localised word or two, large enough to
   read on a phone, and they come from the same `strings.xml` the game uses.

Do not mix: a screenshot set that is half localised and half English reads as an
oversight and costs more credibility than it earns.

## Notes for whoever picks this up

### The French full description had two defects, now fixed

The draft originally contained an untranslated English word (`chasing`) and an
instruction to itself in the middle of the copy. Both are corrected above. They
were not caught by any test because **Play Console copy is not in the
repository** - there is nothing to run a check against. Copy of this kind needs a
human pass, and the two sections that still need one are flagged in place rather
than fixed in passing.

### What is *not* translated, and why

| Item | Kept as-is | Reason |
| --- | --- | --- |
| App name / store title | "Arrow Puzzle" | Brand and search term; see the decision above |
| The ARROW PUZZLE wordmark in the splash and menu | English, Poppins | Drawn lettering, not text. It is the logo |
| Arrow direction names (`UP`, `RIGHT`, …) | English | Level-asset identifiers parsed by the engine |
| Level and pack filenames | unchanged | Read from `assets/levels`, not user-visible |
| Package name, class names, resource keys | unchanged | Technical identifiers |

### Adding an eighth language

The whole of it:

1. Add an entry to `AppLanguage` with its BCP 47 tag and its endonym's string
   resource.
2. Copy `res/values/strings.xml` to `res/values-<tag>` and translate it.
3. Add the `language_*` endonym for it to all eight files.
4. Run `.\gradlew.bat testDebugUnitTest`. `L10nStringsTest` will fail on any
   missing key, any moved placeholder, any label too wide for its control, and
   any folder name that disagrees with the enum.
5. If it is a CJK script, also add it to `needsSystemFont` in `AppLanguage` so
   the interface family follows - Poppins carries no CJK glyphs.
6. Add the store copy above.
